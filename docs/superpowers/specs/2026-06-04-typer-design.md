# Typer — консольный тренажёр слепой печати

**Дата:** 2026-06-04
**Статус:** дизайн согласован, готов к планированию реализации

## Обзор

Консольный (TUI) тренажёр слепой печати — аналог «Соло на клавиатуре» с
акцентом на геймификацию. Курс из линейно разблокируемых уроков: от базовых
клавиш и их комбинаций до печати связных текстов. Каждый урок проверяет
скорость и долю опечаток; уровень проходится только при выполнении критериев.
Игрок видит свой рост по двум осям (скорость и точность) через бенчмарк-тест,
проводимый в начале и в конце курса.

## Зафиксированные решения

| Параметр | Решение |
| --- | --- |
| Стек | Python 3.13 + Textual (TUI), uv / ruff / ty / pytest |
| Языки печати | Русский (ЙЦУКЕН) и английский (QWERTY); контент в данных |
| Профиль | Один локальный профиль, прогресс на диске (`~/.config/typer/`) |
| Геймификация | XP и уровни игрока, достижения/бейджи, стрики и комбо (без звёзд за уровень) |
| Прогрессия | Линейная с разблокировкой; провал → повтор уровня |
| Режим ввода | Свободный ввод, ошибки красным, исправление через Backspace |
| Локализация | Язык интерфейса — настройка профиля, независимая от языка печати; фолбэк на английский |

## Секция 1. Архитектура и структура модулей

Три слоя с однонаправленным потоком зависимостей: `tui → gamification →
domain → engine`. Движок и предметная модель не знают про Textual, что делает
их тестируемыми без терминала.

```
typer/
├── pyproject.toml            # uv, ruff, ty, pytest
├── content/                  # данные курса (НЕ код)
│   ├── courses/
│   │   ├── ru.yaml           # курс ЙЦУКЕН: уроки по порядку
│   │   └── en.yaml           # курс QWERTY
│   ├── achievements.yaml     # определения бейджей
│   └── i18n/
│       ├── ru.yaml           # ключ → строка интерфейса
│       └── en.yaml
├── src/typer/
│   ├── engine/               # ЧИСТАЯ ЛОГИКА, без терминала
│   │   ├── session.py        # TypingSession: целевой текст + поток нажатий → состояние
│   │   ├── metrics.py        # WPM, точность, опечатки, комбо
│   │   └── keystroke.py      # Keystroke(char, timestamp, kind)
│   ├── domain/               # модель предметной области
│   │   ├── lesson.py         # Lesson, PassCriteria (порог опечаток, мин. WPM)
│   │   ├── course.py         # Course: упорядоченные уроки, разблокировка
│   │   └── progress.py       # Progress, XP, стрики, разблокированные достижения
│   ├── persistence/
│   │   └── store.py          # загрузка/сохранение профиля (JSON, атомарная запись)
│   ├── content_loader.py     # парсинг YAML курсов/достижений/i18n → domain-объекты
│   ├── gamification/
│   │   ├── xp.py             # формула XP, уровни игрока
│   │   └── achievements.py   # движок проверки условий бейджей
│   └── tui/                   # Textual: экраны и виджеты
│       ├── app.py            # TyperApp, навигация между экранами
│       ├── screens/          # menu, lesson, results, progress, achievements
│       └── widgets/
│           └── typing_view.py # рендер текста + захват клавиш
└── tests/                    # зеркалит src/typer/
```

Границы: `engine/` и `domain/` независимы от UI и от времени (таймстампы
инжектятся). `persistence/` и `content_loader.py` — адаптеры на краях.

## Секция 2. Модель урока и курса (YAML-схема)

Каждый урок описывается данными. Пример (`content/courses/en.yaml`):

```yaml
course:
  id: en
  layout: qwerty
  title:
    ru: "Слепая печать — английский"
    en: "Touch typing — English"
  benchmark_text: "the quick brown fox jumps over the lazy dog ..."
  lessons:
    - id: en-01-home-row
      title:
        ru: "Домашний ряд: f j"
        en: "Home row: f j"
      type: keys              # keys | combos | words | text
      stages:
        - "fff jjj fjf jfj"
        - "ff jj ff jj fj fj"
      pass:
        max_error_rate: 0.08  # доля ошибочных нажатий (опечатки/всего)
        min_wpm: null         # на ранних уроках скорость не требуется
      reward_xp: 50

    - id: en-08-words
      title:
        ru: "Частотные слова"
        en: "Common words"
      type: words
      stages:
        - { source: wordlist, count: 40 }
      pass:
        max_error_rate: 0.05
        min_wpm: 25
      reward_xp: 120

    - id: en-15-text
      title:
        ru: "Связный абзац"
        en: "Real paragraph"
      type: text
      stages:
        - { source: corpus, file: "texts/en/quotes.txt", length: 300 }
      pass:
        max_error_rate: 0.04
        min_wpm: 40
      reward_xp: 250
```

Решения:

- **`type`** задаёт траекторию сложности: `keys` → `combos` → `words` → `text`.
- **`pass`** — два независимых критерия: `max_error_rate` (обязателен) и
  `min_wpm` (опционален, `null` на ранних уровнях). Уровень пройден, только
  если выполнены **оба**.
- **`stages`** — явный текст или генератор (`wordlist`/`corpus`), чтобы урок
  давал новый материал, а не одну зазубренную строку.
- **`benchmark_text`** — фиксированный текст курса для замера «до/после».
- Порог опечаток — **доля**, а не абсолютное число: нормирует сложность по
  длине упражнения. Абсолютное количество опечаток всё равно показывается
  игроку.

## Секция 3. Движок печати и метрики

**Модель состояния.** Движок хранит целевой текст и позицию курсора; на каждое
нажатие получает `Keystroke(char, timestamp, kind)` и обновляет состояние.

Виды нажатий:

- **символ совпал** → курсор вперёд, символ `correct`;
- **символ не совпал** → курсор вперёд, символ `error`, счётчик ошибок +1;
- **Backspace** → курсор назад (метка снимается, ошибка остаётся в истории).

```python
@dataclass
class SessionState:
    target: str
    cursor: int
    char_states: list[CharState]   # correct | error | pending
    keystrokes: list[Keystroke]    # полная история с таймстампами
```

**Метрики** (фиксированные определения):

| Метрика | Формула | Смысл |
| --- | --- | --- |
| Опечатки | число нажатий с `kind=error` | все ошибочные нажатия, *включая исправленные* |
| error_rate | `errors / total_char_keystrokes` | критерий прохождения |
| Точность | `1 − error_rate`, в % | показывается игроку |
| Net WPM | `(correct_chars / 5) / minutes` | «полезная» скорость |
| Raw WPM | `(all_chars / 5) / minutes` | сырая скорость, для статистики |
| Время | от первого до последнего нажатия | таймер стартует с первой клавиши |

Принципиальные решения:

- **Опечатка засчитывается в момент ошибки**, даже если позже стёрта Backspace —
  иначе метрика точности обнуляется правками.
- **«Слово» = 5 символов** (индустриальный стандарт WPM) — для сравнимости
  между уроками и с внешними тестами.

**Комбо**: счётчик подряд идущих `correct` нажатий; любой `error` обнуляет.
Максимальное комбо за сессию идёт в награды.

**Граница тестов**: движок — чистая функция от последовательности `Keystroke`
к состоянию/метрикам; таймстампы инжектятся, тесты детерминированы.

## Секция 4. Геймификация

**XP и уровни игрока.** За пройденный урок начисляется `reward_xp`,
умноженный на множители за качество:

```
earned_xp = base_reward
          × accuracy_bonus     # 1.0..1.5 в зависимости от точности
          × speed_bonus        # 1.0..1.3 если превысил min_wpm
          × first_clear_bonus  # ×2 за первое прохождение, ×1 за повтор
```

Уровень игрока растёт по нарастающему порогу: `level_xp = base × level^1.5`.
Это отдельная ось от прохождения уроков — перепрохождение даёт XP, но
`first_clear_bonus ×2` удерживает основную награду за продвижение вперёд (анти-гринд).

**Стрики.** Календарные дни подряд с хотя бы одной завершённой сессией. Храним
`last_active_date` и `current_streak`; пропуск дня рвёт стрик. Длинный стрик
даёт множитель XP.

**Комбо** — из секции 3, влияет на `accuracy_bonus` и разблокирует бейджи.

**Достижения** описываются данными (`content/achievements.yaml`); движок
проверяет условия после каждой сессии:

```yaml
achievements:
  - id: flawless
    title:
      ru: "Безупречно"
      en: "Flawless"
    desc:
      ru: "Пройди урок без единой опечатки"
      en: "Complete a lesson with zero typos"
    condition: { metric: errors, op: "==", value: 0 }
  - id: speed-demon
    title:
      ru: "Скоростной демон"
      en: "Speed demon"
    desc:
      ru: "Достигни 80 WPM в любом уроке"
      en: "Reach 80 WPM in any lesson"
    condition: { metric: net_wpm, op: ">=", value: 80 }
  - id: week-streak
    title:
      ru: "Неделя силы"
      en: "Week of power"
    desc:
      ru: "Стрик 7 дней"
      en: "7-day streak"
    condition: { metric: streak, op: ">=", value: 7 }
```

Движок достижений — маленький интерпретатор условий (`metric` + `op` + `value`)
против метрик сессии и профиля. Гейм-дизайн (что награждать) отделён от движка
(как проверять).

## Секция 5. Локализация

Две независимые оси:

- **Язык печати** — какую раскладку/тексты тренируем (свойство курса).
- **Язык интерфейса** — на каком языке надписи и достижения (настройка профиля).

Разделение даёт матрицу «любой курс × любой UI-язык» (например, английская
раскладка с русским интерфейсом).

Все человекочитаемые строки контента (`title`/`desc` уроков, курсов,
достижений) — словари по локали. UI-строки приложения — в `content/i18n/{ru,en}.yaml`,
используются по ключам.

- Резолв строки контента: `pick_locale(field, locale)`.
- Резолв строки интерфейса: `t(key, locale)`.
- **Фолбэк**: если перевод отсутствует — английский + предупреждение в лог
  (не падение).

## Секция 6. Бенчмарк «до/после» и экран прогресса

**Бенчмарк.** У курса есть фиксированный `benchmark_text`. Замер в трёх точках:

- **Baseline** — один раз перед первым уроком курса (можно пропустить, с
  предупреждением, что не с чем будет сравнивать).
- **Промежуточно** *(опционально)* — тот же тест из меню в любой момент.
- **Final** — автоматически после прохождения последнего урока.

Каждый замер сохраняет снимок `{date, net_wpm, accuracy, errors}`. Текст один и
тот же → замеры строго сравнимы.

Бенчмарк — **отдельный тип сессии**: его нельзя провалить, он не даёт XP и не
влияет на разблокировку; только пишет снимок в историю. Это защищает сравнение
«до/после» от искажения тренировкой на самом тесте.

**Экран прогресса** показывает две оси — скорость и точность:

```
┌─ Прогресс курса: English (QWERTY) ──────────────────┐
│  Скорость (WPM)            Точность (%)              │
│   60 ┤           ╭●  final  100 ┤         ╭──●        │
│   40 ┤      ╭───╯           96 ┤    ╭───╯            │
│   20 ┤  ●──╯  baseline      92 ┤ ●──╯  baseline      │
│      └──┬────┬────┬──            └──┬────┬────┬──     │
│  Рост: +34 WPM (×2.7)   Опечатки: 12% → 3%           │
│  Уроки: ████████░░ 12/15      Игрок: Lv.7  (3520 XP) │
│  Текущий стрик: 5 дней 🔥     Достижений: 8/20       │
└──────────────────────────────────────────────────────┘
```

Спарклайны строятся из истории сессий и точек замеров.

## Секция 7. Обработка ошибок и граничные случаи

**Ввод:**

- Backspace в начале строки — игнорируется (курсор не уходит в минус).
- Спецклавиши: Esc — пауза/выход с подтверждением; стрелки/Tab игнорируются в
  `TypingView` (не считаются опечатками).
- Paste — блокируется/игнорируется, чтобы не накручивать WPM (Textual различает
  paste-события).
- Несоответствие раскладки ОС — подсказка «переключите раскладку», без
  принудительной смены раскладки ОС (вне нашей власти; честнее предупредить,
  чем молча считать опечатки).
- Юникод — сравнение по кодовым точкам с нормализацией NFC.

**Данные и хранилище:**

- Битый/отсутствующий YAML — fail fast с понятным сообщением (файл, строка,
  причина).
- Повреждённый профиль — бэкап (`profile.json.corrupt-<timestamp>`) и старт с
  чистого профиля с предупреждением; прогресс не теряется молча.
- Отсутствует перевод — фолбэк на английский + предупреждение.
- Запись профиля — атомарная: temp-файл + `rename`, чтобы прерывание не оставило
  полупустой файл.

## Секция 8. Стратегия тестирования

Тестируем поведение, не реализацию. Тяжесть тестов — на чистых слоях.

| Слой | Что тестируем | Как |
| --- | --- | --- |
| `engine` | метрики WPM/точность/опечатки, комбо, Backspace | pytest, фиктивные таймстампы, property-тесты (hypothesis) на инвариантах |
| `domain` | критерии прохождения (оба порога), разблокировка | табличные тесты на граничных значениях |
| `gamification` | формула XP, переходы уровней, логика стриков (вкл. разрыв), достижения | детерминированные тесты с инжектом даты |
| `persistence` | round-trip, восстановление из битого файла, атомарность | tmp-директории, имитация повреждения |
| `content_loader` | парсинг YAML, фолбэк локали, ошибки схемы | фикстуры валидного и битого YAML |
| `tui` | smoke-тесты экранов и навигации | Textual pilot-тесты (минимально) |

Ошибки и границы тестируем наравне со счастливым путём: пустой ввод,
ровно-на-пороге опечаток, разрыв стрика, отсутствующий перевод, битый профиль.

## Открытые вопросы для фазы планирования

- Конкретное наполнение курсов (число уроков, точные пороги по этапам) —
  детализируется при написании контента.
- Источники текстов/словарей для генераторов `wordlist`/`corpus`.
- Точные коэффициенты бонусов XP и кривой уровней — подбираются при балансировке.
